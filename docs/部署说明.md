# Docker 部署说明

生产环境采用阿里云容器镜像服务 ACR 构建，服务器只拉取镜像运行。完整流程见根目录[DEPLOY.md](../DEPLOY.md)。

一期使用单应用容器和 SQLite 数据库。注册用户可以选择账户余额或在线支付，游客只能使用在线支付：

```text
浏览器 -> HTTPS 反向代理 -> 应用容器 :3000
                                  |
                                  `-> /app/data/card.db

在线支付服务商 -> HTTPS 回调地址 -> 应用容器支付回调接口
```

应用容器同时提供 Vue 静态文件、Go API、余额事务购买、在线支付回调处理和在线订单过期扫描。TLS 与反向代理由宿主机的 Nginx、Caddy 或宝塔站点处理。

## 1. 准备

服务器需要安装 Docker Engine 24+ 和 Docker Compose v2，并开放站点使用的 HTTP/HTTPS 端口。服务器不需要安装 Node.js 或 Go，也不在服务器执行镜像构建。

```bash
mkdir -p /www/docker/card/data
cd /www/docker/card
```

服务器只需要`docker-compose.yml`、`.env`、`config.json`和`data/`。编辑`.env`，填写阿里云镜像地址、外部域名、应用密钥、卡密加密密钥和支付服务商参数。生产环境必须修改全部示例密钥和管理员密码。

当前仓库内置的`mock`支付只用于开发验收。正式上线前必须按最终支付服务商文档完成下单接口适配；只填写商户参数不会自动获得真实收款能力。

## 2. SQLite 要求

- 数据库文件固定存放在挂载目录`/app/data/card.db`。
- 只运行一个应用实例，不能让多个容器同时写同一个 SQLite 文件。
- 宿主机数据目录必须允许容器内应用用户读写。
- 应用启动时启用 WAL、外键约束和写锁等待时间。
- 不要把数据库写入容器镜像层，否则重建容器会丢失数据。

## 3. 在线支付回调

回调基础地址由`APP_BASE_URL`和`PAYMENT_PROVIDER`组成：

```text
https://card.example.com/api/v1/webhooks/payments/provider-name
```

要求：

- 域名已配置有效 HTTPS 证书。
- 公网可以访问回调地址。
- 反向代理不得缓存或修改回调请求体。
- 支付服务商密钥只保存在`.env`。
- 上线前通过服务商沙箱测试正确签名、错误签名和重复回调。

## 4. 构建与启动

仓库根目录提供多阶段`Dockerfile`，由阿里云 ACR 构建 Vue 前端和 Go 单二进制。最终镜像由 Go 在`:3000`同时提供 API 和前端静态文件。

阿里云 ACR 绑定 Git 仓库后使用：

```text
构建上下文：/
Dockerfile：/Dockerfile
镜像版本：latest
```

服务器首次启动：

```bash
docker login --username=你的阿里云镜像仓库用户名 registry.cn-hangzhou.aliyuncs.com
docker compose pull
docker compose run --rm app seed-catalog --replace
docker compose up -d
docker compose ps
curl --fail http://127.0.0.1:${APP_PORT:-3201}/healthz
```

`seed-catalog --replace`只用于首次部署或明确需要清空并重建平台目录的环境，它会删除现有目录关联数据，升级时不要执行。

访问`APP_BASE_URL`，分别完成注册用户余额购买、注册用户在线支付，以及游客在线支付和查单测试。

查看日志和停止服务：

```bash
docker compose logs -f --tail=200 app
docker compose down
```

## 5. 配置文件

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 构建 Vue 静态资源和 Go 应用的多阶段镜像 |
| `docker-compose.yml` | 单应用容器定义 |
| `.env` | 生产连接参数和密钥，不提交 Git |
| `.env.example` | 环境变量模板 |
| `config.json` | 非敏感业务开关 |
| `${APP_DATA_DIR}/card.db` | SQLite 主数据库 |

## 6. 数据库迁移

应用启动时会通过 GORM 自动执行可重复的表结构迁移。升级上线顺序：

```bash
docker compose pull
docker compose up -d
docker compose ps
curl --fail http://127.0.0.1:${APP_PORT:-3201}/healthz
```

迁移失败时应用会拒绝启动，不得绕过错误继续运行新版本。涉及破坏性字段变更时，应另行编写版本化迁移并先在备份副本演练。

## 7. 备份与恢复

- 使用 SQLite Backup API、`.backup`或等价的安全在线备份方式。
- WAL 模式运行时不能只复制`card.db`而忽略配套状态。
- 数据库每日备份，至少保留 7 天。
- `CARD_ENCRYPT_KEY`和`CONTACT_ENCRYPT_KEY`必须单独备份。
- 数据库备份和加密密钥不要只保存在同一台服务器。
- 上线前演练数据库恢复、余额流水核对、联系方式解密和 CDK 解密读取。
