# Docker 部署说明（宝塔 / 宿主机数据库风格）

部署方式对齐 `image2api`：

- **只跑一个应用容器**（预构建镜像）
- 配置全部走 **根目录 `.env`**
- **PostgreSQL / Redis 在宿主机**（宝塔安装），容器通过 `host.docker.internal` 访问
- 宿主机端口映射到容器 **80**

```
浏览器 → 宿主机 APP_PORT → 容器 :80（卡网服务）
                ↓
        host.docker.internal
                ↓
     宝塔 PostgreSQL / Redis
```

## 1. 准备

```bash
# 在服务器项目目录
cp .env.example .env
# 编辑 .env：镜像名、端口、DATABASE_URL、密钥、SMTP、域名等

# 确保配置文件与数据目录存在
mkdir -p /www/docker/card/data
# 若 APP_CONFIG_FILE 指向该路径，把 config.json 放过去
cp config.json /www/docker/card/config.json
```

在宝塔创建 PostgreSQL 库与用户，与 `.env` 里 `DATABASE_URL` 一致。  
Redis 若已装，确认 `REDIS_URL` 端口与密码。

## 2. 启动

```bash
docker compose pull
docker compose up -d
docker compose ps
docker compose logs -f app
```

访问：`http://服务器IP:APP_PORT` 或已反代的 `APP_BASE_URL`。

## 3. 关键文件

| 文件 | 作用 |
|------|------|
| `docker-compose.yml` | 单服务 `app`，读 `.env` |
| `.env` | **不进 Git**，生产密钥 |
| `.env.example` | 模板，可提交 |
| `config.json` | 站点业务开关，挂载进容器 |

## 4. 与「全栈 Compose 内置 Postgres」的区别

| | 本方案（当前） | 全栈内置 |
|--|----------------|----------|
| 数据库 | 宿主机 / 宝塔 | compose 内 postgres 服务 |
| 运维 | 和现有 image2api 一致，易备份 | 一键但要自己管 volume |
| 镜像 | 阿里云 `IMAGE_NAME` 拉取 | 也可本地 build |

当前按你的习惯采用 **镜像拉取 + 宿主机库**。本地开发若要内置 DB，可另加 `docker-compose.dev.yml`。

## 5. 镜像构建（代码就绪后）

```bash
# 示例：构建并推阿里云
docker build -t registry.cn-hangzhou.aliyuncs.com/your-namespace/card:latest .
docker push registry.cn-hangzhou.aliyuncs.com/your-namespace/card:latest
# .env 中 IMAGE_NAME 与上述一致后
docker compose pull && docker compose up -d
```

## 6. 注意

- 不要把真实 `.env` 提交到 GitHub
- `CARD_ENCRYPT_KEY` / `JWT_SECRET` / `APP_AUTH_KEY` 必须更换并备份
- 支付回调 URL 需公网可达，一般配 Nginx/Caddy 反代到 `APP_PORT`
