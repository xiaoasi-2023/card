# 代理卡密销售平台（卡网）规划文档

> 对标产品：https://www.888proxy.com/  
> 定位：自备卡密池为主、多级子代理分销、邀请下单返利的自动化卡密商城  
> 部署：Docker 一键部署  
> 技术栈：后端 Go（推荐）/ Python，前端 Vue 3 SPA

---

## 1. 产品定位与目标

### 1.1 要做什么

做一个类似 888proxy 的**代理 IP 卡密自动发卡商城**：

- 用户选品 → 支付 → **秒发卡密**（CDK）
- 支持游客下单查单、会员中心、余额充值
- **主站 + 多级子代理（多开子店）** 分销体系
- **邀请人下单返利**（固定 0.5 / 1 元，不可提现，仅作站内余额）

### 1.2 核心前提（已确认）

| 前提 | 说明 |
|------|------|
| 卡密自备 | 七大平台卡密均已持有，**卡密池为发货主路径** |
| 上游 API | 可选增强，不阻塞上线；先做人工导入 / 批量入库 |
| 多开子代理 | 必须规划：总站开一级代理，一级可再开子代理 |
| 邀请返利 | 被邀请人下单，邀请人得固定金额；**不可提现**，只能当余额买卡 |

### 1.3 支持的平台（卡密品类）

| 平台 | 官网 | 卡密来源 |
|------|------|----------|
| CliProxy | https://cliproxy.com/ | 自备 CDK 入库 |
| Kookeey | https://www.kookeey.com/ | 自备 CDK 入库 |
| B2Proxy | http://b2proxy.com/ | 自备 CDK 入库 |
| 711Proxy | https://711proxy.com/ | 自备 CDK 入库 |
| IPWEB | https://www.ipweb.cc/ | 自备 CDK 入库 |
| BunnyProxy | https://app.bunnyproxy.com/ | 自备 CDK 入库 |
| UdealProxy | http://www.udealproxy.com | 自备 CDK 入库 |

后续可扩展任意「卡密类」商品（不限代理 IP）。

## 3. 核心业务设计

### 3.1 发卡模型：卡密池优先

```
下单支付成功
    │
    ▼
锁定订单 SKU 数量 N
    │
    ├─ 卡密池剩余 >= N  ──► 分配 N 张（状态：已售，绑定 order_id）
    │                         写发货记录，通知用户
    │
    └─ 不足  ──► 订单标记「缺货/待补货」
                  通知管理员；支持到货后自动补发或退款
```

**卡密状态机**

```
available（可用）
    → locked（下单锁定，防超卖，超时释放）
    → sold（已售出）
    → void（作废 / 已失效）
    → recycled（可选：售后回收再审）
```

**入库方式**

1. 后台粘贴 / 上传 txt、csv（一行一卡或 `卡号----密码`）
2. API 批量导入（总站 / 授权代理）
3. （二期）上游平台 API 自动拉卡 — 适配器模式，不阻塞一期

**库存展示**

- 前台可显示：充足 / 紧张 / 售罄，或具体数字（可配置）
- 后台精确：可用 / 锁定 / 已售 / 总量

### 3.2 双轨资金体系（必须严格分账）

| 账户类型 | 字段建议 | 来源 | 用途 | 能否提现 |
|----------|----------|------|------|----------|
| 充值余额 | `balance_recharge` | 用户在线充值、礼品卡 | 买卡、抵扣 | ❌（用户侧一般不提现；代理另算） |
| 返利余额 | `balance_rebate` | 邀请下单返利 | **仅买卡** | ❌ **禁止提现** |
| 代理佣金 | `balance_commission` | 差价 / 佣金结算 | 提现到支付宝/USDT 等 | ✅ 可提现 |

**下单扣款优先级（建议）**

```
1. 返利余额（强制优先消耗，促活）
2. 充值余额
3. 在线支付补差价
```

**设计原则**

- 返利与佣金**分表分字段**，任何提现接口不得读取 `balance_rebate`
- 所有变动写 `wallet_ledger`（流水），含 `account_type`、`biz_type`、`ref_id`
- 后台调账需二次确认 + 操作日志

### 3.3 邀请下单返利

**规则（可配置）**

| 项 | 默认建议 | 说明 |
|----|----------|------|
| 返利金额 | ¥0.5 或 ¥1 | 后台全局 / 活动可配 |
| 触发条件 | 被邀请人**支付成功且订单完成（已发卡）** | 避免未支付刷单 |
| 返利对象 | 直接邀请人（一级） | 一期不做多级裂变返利，避免与代理佣金混淆 |
| 到账账户 | `balance_rebate` | 不可提现 |
| 单用户贡献上限 | 可配（如邀请人累计从同一人得返利 ≤ N 次） | 防刷 |
| 新客定义 | 首次下单 / 注册后绑定 | 注册时填邀请码或链接 `?ref=CODE` |
| 自邀 | 禁止 | 同实名/同设备/同支付账号检测 |

**流程**

```
用户 A 分享邀请链接 / 码
    → 用户 B 注册绑定 inviter_id = A
    → B 下单支付成功并发货
    → 生成 rebate_record（pending → success）
    → A.balance_rebate += 配置金额
    → 写 ledger
```

**与代理佣金的区别**

| | 邀请返利 | 代理佣金 |
|--|----------|----------|
| 关系 | 社交邀请 | 商业分销合同 |
| 金额 | 固定小额 | 差价或比例 |
| 账户 | 返利余额 | 佣金余额 |
| 提现 | 否 | 是 |
| 目的 | 拉新促购 | 渠道利润 |

### 3.4 多级子代理（多开）

#### 3.4.1 层级模型

```
总站（Platform / Tenant root）
 └── 一级代理 Agent L1（可绑定独立域名或 sub.domain）
      └── 二级代理 Agent L2
           └── 三级代理 Agent L3（建议默认最多 3 级，可配）
```

- 每个代理 = 一个**逻辑店铺（shop/tenant）**
- 用户下单归属「入口店铺」；佣金按层级规则向上结算
- 卡密默认从**总站统一卡池**扣减（保证货源与风控）；高级代理可申请「独立卡池」权限

#### 3.4.2 开户与授权

| 能力 | 说明 |
|------|------|
| 开户 | 上级或总站创建代理账号，生成 shop_id、invite/agent code |
| 商品授权 | 可售 SKU 白名单；未授权不可见 |
| 价格 | 上级给出「供货价」；下级设定「销售价」≥ 供货价 |
| 域名 | 一级建议独立域名；二三级可用 path 或二级子域 |
| 状态 | 正常 / 冻结 / 清退（冻结后不可下单，已售卡密仍可查） |

#### 3.4.3 定价与佣金

**模式 A：差价模式（推荐默认）**

```
总站成本价 C
L1 供货价 P1（总站设）
L1 售价 S1（L1 设，面向 C 端或 L2）
L2 供货价 P2（L1 设）
L2 售价 S2

用户在 L2 店买：支付 S2
结算：
  - 总站收入：P1（或 C + 总站毛利，按实现选一种记账）
  - L1 佣金：P2 - P1
  - L2 佣金：S2 - P2
```

实际入账以「订单分账快照」为准，下单时固化各级价格，避免事后改价扯皮。

**模式 B：比例佣金**

```
用户支付 S
总站保留 (1 - r1)
L1 得 S * r1，再分给 L2: S * r2
```

一期建议 **差价模式**，好理解、少纠纷。

#### 3.4.4 提现

- 仅 `balance_commission` 可申请提现
- 审核：自动（小额）/ 人工（大额）
- 通道：支付宝、USDT、银行卡（可配）
- 手续费、最低额度、每日限额 — 后台配置
- **返利余额不可进入提现单**

#### 3.4.5 数据隔离

- 代理只能看**本店及下级**订单与用户（可配是否可见下级明细）
- 卡密明文：仅总站与「订单归属客服角色」；代理端默认看脱敏（前 ped 后）或仅订单状态
- 防止下级代理导出全站卡密

### 3.5 订单与支付

**订单状态**

```
created → paying → paid → delivering → completed
                 ↘ expired / cancelled
         paid → refunding → refunded
         paid → deliver_failed（缺货）
```

**支付通道（对标 888proxy，按需启用）**

| 通道 | 场景 |
|------|------|
| 易支付 epay | 国内支付宝/微信聚合 |
| Epusdt / 自建 USDT | 加密货币 |
| 支付宝官方 | 可选 |
| 微信官方 | 可选 |
| Stripe | 国际卡 |
| PayPal | 国际 |
| 余额支付 | 站内两类余额 |

回调：验签 → 幂等更新订单 → 触发发卡 → 触发返利 / 佣金结算。

### 3.6 游客下单

- 邮箱（必填）+ 可选手机
- 生成 `order_no` + `query_token`
- 查单：`/guest/orders` 输入订单号+邮箱或 token 链接
- 卡密仅展示给订单凭证持有者；邮件发送副本

## 4. 系统架构

### 4.1 总体架构

```
                    ┌─────────────┐
                    │  Nginx/Caddy │  TLS、反代、静态资源
                    └──────┬──────┘
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
    ┌────────────┐  ┌────────────┐  ┌────────────┐
    │ 用户 SPA   │  │ 代理后台   │  │ 总站 Admin │
    │ (Vue3)     │  │ (Vue3)     │  │ (Vue3)     │
    └─────┬──────┘  └─────┬──────┘  └─────┬──────┘
          └───────────────┼───────────────┘
                          ▼
                 ┌────────────────┐
                 │  API Gateway   │  鉴权、限流、租户解析
                 │  (或直接 API)  │
                 └────────┬───────┘
                          ▼
                 ┌────────────────┐
                 │  业务服务 API  │  Go (Gin/Fiber) 推荐
                 │  monorepo/模块 │  或 Python (FastAPI)
                 └────────┬───────┘
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
   ┌────────────┐  ┌────────────┐  ┌────────────┐
   │ PostgreSQL │  │   Redis    │  │  对象存储  │
   │ 主数据     │  │ 会话/锁/队列│  │ 导出/凭证  │
   └────────────┘  └────────────┘  └────────────┘
                          │
                          ▼
                 ┌────────────────┐
                 │ Worker 异步任务 │ 发信、结算、预警、上游同步
                 └────────────────┘
```

### 4.2 技术栈选型

| 层 | 推荐 | 备选 | 理由 |
|----|------|------|------|
| 后端 | **Go + Gin/Fiber + ent/GORM** | Python FastAPI + SQLAlchemy | 并发发卡、支付回调、代理树查询；单二进制易 Docker |
| 前端 | Vue 3 + Vite + Pinia + Vue Router | React | 对标 888proxy 技术路线，生态成熟 |
| UI | Naive UI / Element Plus | — | 中后台快；商城可部分定制 |
| DB | PostgreSQL 16 | MySQL 8 | JSONB、事务、树查询友好 |
| 缓存 | Redis 7 | — | 库存锁、会话、限流、队列 |
| 队列 | Redis Stream / asynq | Celery（若 Python） | 发卡、邮件、结算 |
| 文档 | OpenAPI | — | 前后端契约 |
| 部署 | Docker Compose | K8s（后期） | 一期足够 |

**结论：一期推荐 Go 后端 + Vue3 前端 + Postgres + Redis + Docker Compose。**

### 4.3 多租户解析

```
请求进入
  → Host: agent1.example.com  或  X-Shop-Code / path /shop/{code}
  → 解析 shop_id
  → 上下文注入：价格策略、主题、支付配置（可继承总站）
```

### 4.4 关键安全设计

- 库存扣减：Redis Lua 或 DB `SELECT … FOR UPDATE`，防超卖
- 卡密加密：DB 内加密存储（AES-GCM），密钥走环境变量 / KMS
- 支付回调：IP 白名单 + 签名 + 幂等键
- 接口：JWT（用户/代理/管理员分 iss 或 type）+ RBAC
- 邀请反作弊：IP/设备指纹/支付账号关联限频
- 审计：管理端高危操作全量日志

## 9. 风控与合规要点

1. **邀请反刷**：同 IP 注册上限、同设备、支付账号关联、邀请人日返利上限、异常订单不计返利  
2. **卡密安全**：加密存储、展示限次、禁止代理批量导出未售卡、操作审计  
3. **资金安全**：返利账户无提现入口；提现人工审核；分账快照不可篡改  
4. **超卖**：下单锁库存 + 支付超时释放 + 发卡事务  
5. **内容与业务合规**：代理 IP 属工具类商品，需自行确保经营资质与用户协议免责条款

## 10. 分期路线图

### 一期（MVP，可售卖）

- 用户注册登录、商品 SKU、**卡密批量导入与自动发卡**

## 13. 决策汇总

| 决策项 | 结论 |
|--------|------|
| 对标 | 888proxy 类卡网 SPA |
| 货源 | **自备卡密池为主**；上游 API 后期可选 |
| 平台品类 | 七家代理平台 CDK + 可扩展 |
| 分销 | **多级子代理**，差价结算，佣金可提现 |
| 拉新 | **邀请下单返利 0.5/1 元**，入账返利余额，**不可提现** |
| 资金 | 充值余额 / 返利余额 / 代理佣金 **三账分离** |
| 技术 | Go + Vue3 + Postgres + Redis |
| 部署 | Docker Compose，反向代理 TLS |
