# 阿巳全链路融合规划

> 状态：规划已确认方向，分阶段实施  
> 更新日期：2026-07-28  
> 范围：公开站门户、商品橱窗、统一兑换、闲鱼/联动小铺销售、四类履约站

---

## 1. 目标与约束

### 1.1 目标

把分散的服务收成一条对用户清晰的链路：

```text
逛公开站橱窗
  → 去联动小铺（或闲鱼）付款
  → 获得兑换码 / 领取码
  → 回公开站统一兑换
  → 按品类履约（账号 / 积分 / 流量卡密 / 中转额度）
```

用户只需要记住一个门面域名：`https://card.xiaoasi.xyz`。

### 1.2 硬约束

1. **自己暂时无法对接支付**，收款必须外置（联动小铺、闲鱼）。
2. **项目可以多，路径必须少**：不把四个仓库揉成一个 monorepo，但用户路径统一。
3. **履约分库**：账号、积分、流量字符串、中转额度，业务模型不同，库存不合并。
4. **兑换码前缀区分品类**，公开站按前缀路由到对应系统。
5. **数字商品交付后不退不换**（文案全站统一）。

### 1.3 非目标（明确不做）

- 近期不把 `card` 前台商城当正式收款站推广。
- 不把图像积分账本、中转账本迁入 `kiro-card-system`。
- 不做全站统一会员单点登录（可后期再议）。
- 中转站本期只规划接口位，**兑换直接提示失败（未开放）**。

## 2. 系统角色总览

| 系统 / 站点 | 路径或域名 | 角色 | 管什么 |
|---|---|---|---|
| 公开站门户 | `https://card.xiaoasi.xyz`（`kiro-card-system/public-site`） | **唯一用户门面** | 服务导航、商品橱窗、统一兑换柜面 |
| 联动小铺 / 闲鱼 | 外部平台 | **收款与推广** | 收钱、自动/人工发兑换码 |
| Kiro 卡密系统 | `kiro-card-system` | **账号履约** | 账号池、KIRO 卡密生成与兑换 |
| 图像工作台 | `chatgpt2img`（`image.xiaoasi.xyz`） | **积分履约** | 用户积分、IMG CDK 核销 |
| 流量 / 代理库存 | 本仓库 `card` | **字符串卡密履约** | 上游卡密入库、领取揭示、查单 |
| 中转站 | 后续（如 `ai.xiaoasi.xyz` 一类） | **额度履约（规划）** | API 额度 / 中转 CDK（暂不开发） |

### 2.1 一句话定调

> **收款在外，门面在公开站，履约分库。**  
> 合的是用户路径和发货话术，不是把代码仓库揉成一个。

## 3. 公开站结构

```text
https://card.xiaoasi.xyz
├─ /                 服务台首页（已有）：服务导航 + 精选商品入口
├─ /shop             商品橱窗（新建）：展示 + 外链购买 + 去兑换
└─ /redeem           统一兑换中心（现有 redeem 升级）：多品类领货柜面
```

### 3.1 首页

- 保留现有：账号兑换中心、AI 图像工作台、API 模型等服务卡。
- 增加「精选商品 / 进入橱窗」入口，不把首页做成纯商城。
- **服务是用，橱窗是买**，两类入口分开。

### 3.2 商品橱窗 `/shop`

#### 定位

只做三件事：**看懂卖什么 → 去小铺付款 → 回来兑码**。

不做：登录、余额、结账、在线支付、购物车。

#### 页面结构

| 区块 | 内容 |
|---|---|
| 顶栏 | 服务台 · 商品橱窗 · 兑换中心 · 图像工作台 |
| 购买说明条 | 3 步：选商品 → 联动小铺付款 → 回本站兑码 |
| 分类 | 账号 / 图像积分 / 流量代理 / 中转额度（中转可灰显「即将开放」） |
| 商品卡网格 | 见下表字段 |
| FAQ | 怎么兑、到账方式、不退款、闲鱼也可购 |

#### 商品卡字段

```text
标题、副标、展示价、标签（热销/即时兑换…）
一句用途说明
主 CTA：去购买（联动小铺外链，新窗口）
次 CTA：已有兑换码（跳 /redeem，可带 type 预选）
库存状态：有货 / 紧张 / 缺货（第一期可手写）
```

#### 第一期实现建议

- **商品数据与页面模板分离**：见下文「3.3 静态商品配置」。
- 视觉延续公开站现有深色黄铜风（不必强行套 `card` 蓝橙）。
- 规格少可不做详情页；规格多再加轻量说明页，购买仍外链。

#### 橱窗统一话术

> 付款后获得兑换码 → 打开 card.xiaoasi.xyz/redeem 领取。  
> 数字商品交付后不退不换。支持闲鱼与联动小铺购买。

## 3.3 静态商品配置（第一期，可运营改）

第一期橱窗**不接后端商品 API**。商品列表单独放配置文件，改价、上下架、换小铺链接只改配置，不改 HTML 结构。

### 3.3.1 文件位置

路径在公开站仓库：

```text
kiro-card-system/public-site/
├─ index.html
├─ redeem.html
├─ shop.html                 # 待建：读配置渲染橱窗
└─ data/
   ├─ products.js            # 运行时主配置（页面 script 引入）
   ├─ products.json          # 同结构 JSON，备份/对照/以后导入
   └─ README.md              # 运营改法说明
```

| 文件 | 是否页面加载 | 说明 |
|---|---|---|
| `data/products.js` | **是** | 定义 `window.ASI_SHOP`；纯静态、无 fetch，最省事 |
| `data/products.json` | 否（第一期） | 与 js 同结构；改完 js 建议同步 json，防漂移 |
| `data/README.md` | 否 | 给运营的最短说明 |

> 约定：**以 `products.js` 为运行真相**；`products.json` 为可编辑镜像。  
> 后期若上管理端，可改为只维护 JSON，构建时生成 js，或 shop 页 fetch JSON。

### 3.3.2 页面如何引用

```html
<script src="data/products.js"></script>
<script>
  const shop = window.ASI_SHOP;
  const list = shop.getEnabledProducts();              // 全部上架商品
  const hot  = shop.getEnabledProducts({ featuredOnly: true });
  const img  = shop.getEnabledProducts({ categoryId: "image" });
</script>
```

首页精选、橱窗网格、分类 Tab 都读同一份配置。

### 3.3.3 配置结构

```text
ASI_SHOP
├─ version / updatedAt
```

### 3.3.6 库存状态枚举

| 值 | 展示（可改 labels） | 购买按钮 |
|---|---|---|
| `in_stock` | 有货 | 有 buyUrl 则可点 |
| `low` | 紧张 | 可点 |
| `sold_out` | 缺货 | 禁用 |
| `coming_soon` | 即将开放 | 禁用 |

`ASI_SHOP.canBuy(product)` 规则：

```text
enabled === true
且 buyUrl 非空
且 stockStatus 不是 sold_out / coming_soon
且 fulfillment 不是 relay（中转未开放）
```

### 3.3.8 运营日常怎么改

1. 打开 `public-site/data/products.js`
2. 找到对应商品对象
3. 常见修改：
   - 上架：`enabled: true`，填好 `buyUrl`
   - 下架：`enabled: false`
   - 改价：改 `priceYuan` 和/或 `priceText`（与小铺标价一致）
   - 缺货：`stockStatus: "sold_out"`
   - 换小铺链接：只改 `buyUrl`
   - 首页是否露出：`featured: true/false`
4. 同步改 `products.json`（建议）
5. 刷新 `shop.html` / 首页即可

**不要**把小铺链接写死在 HTML 里；**不要**为改一个价去动样式大段代码。

## 4. 码规范与前缀

| 前缀 | 品类 | 小铺发出的 | 客户回站后得到 | 履约系统 |
|---|---|---|---|---|
| `KIRO-` | 账号 | 兑换卡密 | 真实账号凭据 | kiro-card-system |
| `IMG-` | 图像积分 | CDK | 账户积分增加 | chatgpt2img |
| `TRAF-` | 流量/代理 | 领取码 | 上游可用真卡密明文 | card 项目 |
| `RELAY-` | 中转额度 | CDK（规划） | 中转额度增加 | 中转站（未开发） |

规则：

1. 前缀全局唯一语义，闲鱼与小铺用**同一套码**，不发明第二套格式。
2. 码一次性成功核销；重复兑应明确失败。
3. 未识别前缀：提示「兑换码无效或品类未开放」。
4. `RELAY-` 识别后**固定返回未开放/失败**，直到中转站接口就绪。

## 5. 统一兑换中心 `/redeem`

### 5.1 总交互

```text
用户打开 /redeem
  → 选择或自动识别品类（可按前缀）
  → 按品类展示表单
  → 提交
  → 公开站路由到对应履约系统
  → 统一结果区展示 + 下一步引导
```

### 5.2 品类表单差异

| 品类 | 用户输入 | 确认步骤 | 成功结果 | 下一步 |
|---|---|---|---|---|
| Kiro 账号 | 卡密 | 无（直接兑） | 账号列表（邮箱/token 等） | 自行保存；可再兑其他码 |
| 图像积分 | ① 图像站登录账号 ② 查询确认 ③ CDK | **必须先查账号确认再兑** | 到账积分、新余额 | 跳转图像工作台 |
| 流量代理 | 领取码（可选查单密码） | 无或简易确认 | 真卡密明文 + 复制 | 去上游平台使用 |
| 中转额度 | 登录账号 + CDK（规划同图像） | 规划同图像 | 规划：额度到账 | 规划：跳转中转站 |
| 中转（当前） | 任意 `RELAY-` 或选择中转 | — | **直接失败：暂未开放** | 提示关注开放时间 |

### 5.3 图像积分兑换交互（已确认，从简）

不做复杂 SSO，不做公开站自建积分账本。流程固定为：

```text
1. 用户输入图像站登录账号（用户名/邮箱，以图像站实际登录标识为准）
2. 点击「查询账号信息」
3. 公开站调用图像站查询接口，展示：昵称/UID/当前积分 等只读信息
4. 用户确认「是我的账号」
5. 输入 CDK，点击「兑换加积分」
6. 公开站调用图像站核销接口
7. 展示：本次增加点数、兑换后余额；提供「打开图像工作台」按钮
```

失败场景（需有明确文案）：

- 账号不存在
- 查询失败 / 频率限制
- CDK 无效、已使用、已作废
- 账号与 CDK 业务规则冲突（若有）

### 5.4 中转站兑换（规划位，暂不开发）

交互对齐图像站：

```text
输入中转站登录账号 → 查询信息 → 确认 → 输入 CDK → 加额度
```

**当前实现要求：**

- 路由表预留 `RELAY-` 与「中转」品类。
- 用户选择中转或输入 `RELAY-` 前缀时，**直接提示失败**，例如：  
  `中转站兑换暂未开放，请稍后再试或联系客服。`
- 不调用任何真实中转接口，不落库成功兑换。

### 5.5 公开站路由伪接口

```text
POST /api/public/redeem-router   （名称可调整；亦可前端直调各站公开 API）
body:
  {
    "category": "kiro" | "image" | "traffic" | "relay",  // 可省略，靠 code 前缀推断
    "code": "XXXX-...",
    "identity": {                 // 图像/中转需要
      "login": "user@example.com"
    },
    "query_password": "..."       // 流量可选
  }
```

路由行为：

| 前缀/品类 | 动作 |
|---|---|
| `KIRO-` | 调 kiro `POST /api/v1/public/redeem` |
| `IMG-` | 先/已查询账号后，调图像站「指定用户兑 CDK」 |
| `TRAF-` | 调 card「领取/揭示」接口 |
| `RELAY-` | **立即失败：未开放** |
| 未知 | 失败：无效兑换码 |

> 第一期也可由前端按品类分别调各站 API，不强制先做 BFF；但产品行为必须一致。

## 6. 四类站点兑换逻辑详述

### 6.1 Kiro 账号（已基本具备）

```text
小铺/闲鱼发 KIRO-xxxx
  → 公开站输入卡密
  → kiro-card-system 公开兑换
  → 从账号池分配账号并标记
  → 返回账号字段给用户保存
```

- 公开站已有 `redeem.html` + `/api/v1/public/redeem`。
- 升级点：并入统一兑换中心 UI；文案标明「账号类」；与其它品类切换共存。

### 6.2 图像积分（简化版，后期接口）

```text
小铺/闲鱼发 IMG-xxxx
  → 公开站：输入图像站登录账号
  → 查询并展示账号信息
  → 用户确认
  → 输入 CDK
  → 图像站核销 CDK 并给该用户加积分
  → 公开站展示结果 + 跳转图像站
```

- 积分账本只在图像站。
- 公开站不做加积分本地账，只做柜面。
- 用户也可继续在图像站站内自行兑换（双入口允许，核销仍在图像站唯一）。

### 6.3 流量 / 代理（对齐回站领货）

```text
上游真卡密入库 card（加密）
  → 为库存生成/绑定领取码 TRAF-xxxx（小铺只发领取码，不发真卡密）
  → 用户付款后得 TRAF-xxxx
  → 公开站输入领取码
  → card 核销领取码、解密返回真卡密
  → 用户复制去上游使用
```

要点：

1. **领取码 ≠ 真卡密**（终局）。真卡密不进小铺。
2. 公开站是流量的**领货柜台**，不是中转跳转页（没有第三个「流量使用站」可跳）。
3. 建议支持「再次查看」：领取码 + 查单密码，或会员订单（若启用）。
4. **过渡期**（若双码未做好）：可临时让小铺直发真卡密，橱窗注明「付款后直接发货」；终局仍应收口到回站揭示。

### 6.4 中转站（规划，兑换失败）

```text
规划：同图像（账号查询 → 确认 → CDK 加额度）
当前：识别为中转即失败提示未开放
```

预留：

- 前缀 `RELAY-`
- 橱窗分类可先隐藏或标「即将开放」
- 兑换中心品类入口可灰显

## 7. 销售渠道逻辑

### 7.1 联动小铺

| 步骤 | 动作 |
|---|---|
| 上架 | 每个 SKU 对应小铺商品，价格与橱窗展示价一致 |
| 发货 | 优先卡密自动发货：预导入对应前缀的兑换/领取码 |
| 售后话术 | 引导至 `card.xiaoasi.xyz/redeem` |

### 7.2 闲鱼

- 路径不变：成交后发**同一套前缀码**。
- 人工从各系统「取下一张未用码」或批量导出后使用。
- 话术与小铺一致。

### 7.3 发货台（运维，建议中期补）

```text
选品类 → 选规格 → 从对应库存取 1 张未用码 → 一键复制 → 标记已发
```

第一期可用：各系统导出 CSV → 灌小铺。  
第二期：统一取码脚本/小管理页。

## 8. `card` 项目需要改的逻辑

### 8.1 定位变更

| 原定位 | 新定位 |
|---|---|
| 对外收款的完整 CDK 商城 | **流量/代理 CDK 库存与领取履约中台** |
| 买家支付为主路径 | 支付主路径外置；前台降级为可选备用 |

### 8.2 保留

- 平台 / 商品 / SKU / 批次 / 加密卡密库存模型
- 管理端导入卡密、去重、审计
- 订单/揭示相关能力中与「已售标记」可复用的部分
- Docker 与部署骨架
- 已重构的用户端样式（备用：他日自营支付可复活）

### 8.3 主路径搁置 / 弱化

- 对外部推广「在本站结账支付」
- 余额充值、复杂会员运营（可保留代码不主推）
- 依赖真实支付通道的上线验收（无支付前不作为主卖场）

### 8.4 需要新增或改造（按优先级）

#### P0 — 库存出货能力

1. **导出未售卡密**（管理端）：按 SKU 导出 `available` 明文，供过渡期灌小铺或运维。  
2. **取下一张未用码**（管理端/运维 API）：防并发重复发放。  
3. 发放后状态：`available` → `sold` / `claimed`，写审计。

#### P1 — 回站领取模型（终局）

1. **领取码层**（推荐）：  
   - 真卡密仍加密存；  
   - 另有 `claim_code`（如 `TRAF-xxxx`）或等价一次性凭证；  
   - 小铺只发 `claim_code`。  
2. **公开领取接口**（给公开站调）：

```text
POST /api/v1/public/traffic/claim
body: { "claim_code": "TRAF-...", "query_password"?: "..." }
success: {
  "product_name": "...",
  "sku_name": "...",
  "secrets": ["真卡密1", ...],
  "claimed_at": "..."
}
```

3. 幂等：同一码第二次成功兑应返回明确「已使用」；可选在校验凭证后允许再次展示明文（售后）。  
4. 频率限制、防爆破（对齐 kiro 公开兑）。

#### P2 — 与橱窗协作

1. 前台主 CTA 可改为「去联动小铺购买」配置项（外链）。  
2. 隐藏或弱化站内结账入口（配置开关即可）。  
3. 管理端商品增加字段：`external_buy_url`、`code_prefix`、`fulfillment_type=traffic`。

#### 不在 card 做的事

- 不接管 Kiro 账号分配  
- 不接管图像积分  
- 不实现联动小铺支付回调（小铺侧发码即可）

### 8.5 与旧「商城支付揭码」关系

- 旧路径：本站支付成功 → 订单完成 → 订单详情揭密文。  
- 新主路径：小铺发领取码 → 公开站 claim → 揭密文。  
- 两套可并存一段时间；对外只宣传新主路径。

## 9. 图像站（chatgpt2img）需要改的逻辑

### 9.1 已有能力（复用）

- 站内 CDK 体系、核销、积分到账  
- 管理端生成 CDK / 渠道 CDK（B2B 渠道 API 可继续服务批发，与 C 端公开站柜面分离）

### 9.2 为公开站柜面需新增（从简）

#### A. 按登录账号查询信息（公开或半公开）

```text
POST /api/public/portal/user-lookup
body: { "login": "用户输入的登录账号" }
response: {
  "exists": true,
  "display_name": "...",
  "user_id": "...",          // 可返回脱敏 ID
  "quota": 123,              // 当前积分
  "masked_login": "ab***@qq.com"
}
```

要求：

- 仅返回兑换确认所需最小字段，避免过度暴露。  
- 强频率限制（按 IP + login）。  
- 不存在时明确 `exists: false`，不要用含糊 500。

#### B. 指定用户核销 CDK 加积分

```text
POST /api/public/portal/cdk-redeem
body: {
  "login": "与查询时同一账号",
  "cdk": "IMG-...."
}
response: {
  "points_added": 300,
  "quota_after": 450,
  "cdk_status": "redeemed"
}
```

要求：

- CDK 全局只成功一次。  
- 幂等：同一 login+cdk 重复请求可返回已成功结果或明确已使用。  
- 完整 CDK 不进普通访问日志 URL。  
- 可选：要求先 lookup 成功的短时 token，防止盲兑；第一期也可用「login + cdk」直兑，依赖限流。

### 9.3 不需要做的（按当前确认）

- 公开站复杂 SSO 登录跳转（非必须）  
- 公开站代建图像站账号（用户应已有图像站账号；无账号则查询失败并引导注册）  
- 把积分库存搬到 kiro 或 card  

### 9.4 与渠道 API 的边界

| 能力 | 对象 | 用途 |
|---|---|---|
| Channel API + SSO | 合作方 / B2B | 批发建码、代兑、进站 |
| Portal lookup + redeem | 公开站 C 端柜面 | 用户自助：查账号 → 兑 CDK |

两套可并存，密钥与限流策略分开。

## 13. 分阶段实施

### 第 1 期 — 门面与话术（最快）

1. **商品静态配置已落地**：`public-site/data/products.js` + `products.json`（见 §3.3）；运营先填 `buyUrl`。  
2. 公开站增加 `shop.html` 静态橱窗：只读 `ASI_SHOP` 渲染，不写死商品。  
3. 首页加橱窗入口 + 精选（`featured: true`）。  
4. 兑换页文案改为多品类；Kiro 继续可用。  
5. 图像 / 流量在兑换页可先写说明 + 引导（图像可暂链到图像站站内兑）。  
6. 中转入口：失败提示。  
7. `card` 前台停止作为主卖场推广；后台继续管流量库存。

**验收：** 陌生人只靠公开站能完成「看见商品 → 去小铺 → 知道回哪兑」；改 `products.js` 不改 HTML 即可上下架。

### 第 2 期 — 流量回站领取 + 灌小铺

1. `card`：导出未售 / 取码；领取码或 claim 接口。  
2. 公开站流量品类接通 claim。  
3. 小铺只发 `TRAF-`（或过渡仍发真卡密但逐步切换）。  
4. 查单/再查看策略落地。

**验收：** 流量一单完整：小铺付款 → 回站 → 见真卡密 → 状态已售。

### 第 3 期 — 图像公开站柜面

1. 图像站：user-lookup + cdk-redeem。  
2. 公开站：查账号 → 确认 → 兑 CDK 完整交互。  
3. 限流、审计、幂等验收。

**验收：** 仅用公开站完成图像加积分，无需先会用图像站兑码页。

### 第 4 期 — 中转开放

1. 中转站实现与图像同构接口。  
2. 去掉公开站失败短路，接入真兑换。  
3. 橱窗上架中转商品。

### 第 5 期 — 可选增强

1. 统一发货台。  
2. 库存只读汇总到橱窗（自动有货/缺货）。  
3. 若具备支付能力：再评估打开 `card` 自营结账（不推翻橱窗模型）。

## 14. 安全与风控基线

1. 所有公开兑换/查询接口：IP 频率限制。  
2. 账号查询防枚举：统一响应时间、错误文案克制、限流。  
3. 完整兑换码不进 URL query、不进普通日志。  
4. 真卡密仅在领取成功响应中出现；管理导出需权限与审计。  
5. 幂等键：图像/中转兑 CDK、流量 claim 均需防重复加账/重复售卖。
